# Frontend Skill Routing

UI work starts from a Refero competitor baseline and our theme/logo, with Impeccable supplying
refinement and finish verification. Read `$refero-design` when establishing a baseline and
`$impeccable` before the first UI edit, including feature work, fixes, and milestone receivers.
This owned routing assigns installed skills their roles; process skills keep their workflow.

### Establish the baseline

Read product requirements, incumbent UI, theme tokens, and actual logo assets first. A coherent
shipped UI or current DESIGN.md supplies the baseline for local fixes even without a prior brief;
research only unresolved choices. For new surfaces or redesigns, use Refero screens for structure
and states, flows for journeys, and styles for visual cues where our theme leaves room. Verify
product, platform, page type, and state, and inspect images for visual claims. Select one primary
reference with deliberate secondary borrowing, then adapt it to our content and capabilities.
Research ends when the unresolved decisions have relevant evidence and adaptation reasons; broaden
only for a named gap, rather than applying the upstream styles-first order or fixed search counts.

Our requirements and brand commitments govern reference adaptations. Map reference roles to our
tokens; use our logo assets. Record mismatches and gaps. With unavailable live Refero access, reuse
sufficient project or user-supplied competitor evidence and report the limitation; if that cannot
establish a new baseline, request the missing reference while continuing independent preparation.
Missing theme/logo assets remain explicit gaps: preserve available identity, keep missing asset slots
honest, and identify the input needed before claiming brand completion.

For a new baseline, run Impeccable context in the product root before recording it; use init when
PRODUCT.md is missing and product context needs capture. Create or update the relevant surface brief
through the resolved Impeccable launcher's `surface-brief read/write` commands. Under Direction
contract, record THESIS, OWN-WORLD, STORY, FIRST VIEWPORT, FORM, and FINISH: adopted URLs/IDs,
structure and behavior to preserve, brand-source paths and role mappings, adaptations, and the finish
condition. FORM identifies the pinned reference baseline, with no fabricated concept-seed key. Keep
this development contract out of served artifacts; reference existing tokens rather than duplicating
the design system. Local fixes can record their evidence in the delivery report instead.

Reuse a user-selected baseline. Otherwise choose a recommended reversible baseline and explain the
choice; ask only for an unresolved tradeoff the user owns or when variants are requested. This
reference-and-brand contract replaces Refero's default three-direction approval and Impeccable
new-work sections 2–5's interview, concept-seed, and option/comp rounds. Build directly from it with
Impeccable's craft floor; an existing user-approved comp stays the target without another option
round. Full visual exploration runs when the user requests it, rather than automatically for new work.

### Public web pages

For a landing page, marketing site, portfolio, or other public one-pager, `$design-taste-frontend`
supplies the art direction on top of the Refero baseline: idea, composition, type, palette, imagery,
and section blueprints, plus its screenshot look-and-fix loop before the Impeccable finish. Our
theme tokens, logo, and product facts still govern its house style. Dashboards, app screens, and
other product UI stay on Refero and Impeccable alone.

### Refine and finish

Use relevant Impeccable refinement commands within the baseline for hierarchy, spacing, copy,
responsive behavior, accessibility, component states, and performance. Fix defects directly; changes
to the selected overall structure or brand need the user's design decision. Preserve product facts,
working behavior, and scope.

Local fixes finish through the relevant refinement playbook's verification. New surfaces or changed
design systems read Impeccable `reference/new-work.md` section 7 and `reference/document.md` for
batched rendered checks, the shipped finish reviewer, and the documenter. Include the pinned baseline,
reference images, brand sources, and this routing in their packets: the real baseline IDs replace
concept-seed and catalog-card inputs on this route, without inventing a roll. New or changed systems
finish with DESIGN.md and `.impeccable/design.json`; extensions preserve incumbent system files.
The Impeccable finish covers Refero's quality gate by checking both baseline fidelity and brand;
verify the real interaction path and required desktop/mobile or shipped native states once through
that process.

Explicit Owl selection replaces this route for the task and retains product and brand constraints.
For a clean comparison, start a fresh agent session after switching; use separate Orca worktrees
with one writer each when both variants write code.
